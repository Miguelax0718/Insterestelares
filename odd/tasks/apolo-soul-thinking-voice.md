# Feature: APOLO Soul Personality, Young Male Voice, and Voice-Synced Thinking State

Objective: Give APOLO a calm, slightly teasing/bothering, playful personality (`soul.md` inspired by Navi from Zelda and TARS from Interstellar), set default TTS voice to `am_puck`, and keep the UI in a thinking animation until audio synthesis is ready so text and voice land together. Branch: `main` (authorized direct deploy flow). Delivery: ask-on-risk.
Runners: `/home/krl0s/development/flutter/bin/flutter test` + `/home/krl0s/development/flutter/bin/flutter analyze` + `server/.venv/bin/python -m pytest -q` + `server/.venv/bin/ruff check .`.

## Specs

- **S1 — Scope (verbatim):** "Demosle un poco de personalidad, quiza un soul.md en el que se diga q es apolo el asistente, calmado, un poco canson y bromista, inspirado en navi de zelda o tars de interestelar. Pongamosle una voz masculina pero no tan grave, como de joven, jugetona y animada. Trataemos de ponerle una animacion de pensar hasta que este la voz y responda ya con texto y voz, no algo antes, tambien mira a ver si es mejorable el tiempo de espera con otro modelo ( sin que suene muy robotico ). Despliega subagentes"
- **S2 — Personality (`soul.md` + runtime instructions):**
  - Create `soul.md` at the repo root defining APOLO's identity: space health assistant dog, calm under pressure, slightly teasing / playfully persistent ("Listen!" / dry wit like TARS with humor setting dialed responsibly, helpful nudges like Navi), warm and concise, never joking during critical medical alerts (`crit` severity or emergency triage stays direct, clear, and supportive).
  - Embed the distilled personality rules into `coreSkill()` (`lib/features/agent/application/core_tools.dart`, `alwaysOn: true`) and `ApoloUrineSkill` (`lib/features/apolo/agent/apolo_urine_skill.dart`) instructions + offline deterministic prompts so the stateless gateway actually receives APOLO's soul on every turn without exceeding prompt budgets.
- **S3 — Young, playful male voice (`am_puck`) & TTS model check:**
  - Benchmarks in `server/README.md` already proved `kokoro-v1.0.int8.onnx` is slower on x86 CPU (1.809 s vs 1.012–1.30 s for fp32) with lower spectral fidelity, and Piper sounds robotic; keep Kokoro-82M fp32 as the adopted model (already scaled Azure Container App to 2 vCPU / 4 GiB, cutting live synthesis to ~1.3 s).
  - User listened to / chose `am_puck` (already live on Azure via `KOKORO_VOICE=am_puck`). Update repository defaults (`server/app/core/config.py`, `server/app/adapters/kokoro_tts.py`, `server/Dockerfile`, `server/.env.example`, `server/README.md`, `docs/DEPLOY.md`; parent updates gitignored `server/.env`).
- **S4 — Voice-synchronized thinking state & animation:**
  - Add `SynchronizedTextToSpeechService` in `lib/features/agent/domain/agent_ports.dart` with `speakSynchronized(String text, {String? voice, String language = 'en-US', required void Function() onAudioReady})`.
  - Implement `SynchronizedTextToSpeechService` on `RemoteTextToSpeechService` (synthesizes WAV first, calls `onAudioReady()`, then calls `_playback.playWav(wavBytes)`), `ResilientTextToSpeechService` (idempotent `onAudioReady()` guard before local fallback or after remote synthesis), and `SpeakingTrackedTextToSpeechService` (does NOT emit `isSpeaking = true` during `speakSynchronized` until `onAudioReady()` fires, while keeping `speak()` unchanged for existing callers/tests).
  - In `AgentConversationController._runOnlineTurn` (and `_runOfflineFallback` when `speakReply` is true): when `speakReply` is true and `tts is SynchronizedTextToSpeechService`, hold `busy: true` and defer `_commitTargetState(done)` until `onAudioReady` fires (with an idempotent `finally` guard so state always commits even on TTS failure or fallback). When `speakReply` is false or `tts` is not synchronized, commit immediately as before.
  - Add `bool isThinking = false` to `ApoloDogWidget` (`lib/features/apolo/presentation/apolo_dog_widget.dart`) with a dedicated thinking animation (eyes glancing thoughtfully + floating orbital thought dots near the helmet + gentle tilt, distinct from `isListening` and `isSpeaking`).
  - In `ApoloHomeScreen` (`lib/features/apolo/presentation/apolo_home_screen.dart`), while `session.busy` is true, pass `isThinking: true` to `ApoloDogWidget` and display a compact animated thinking bubble (no premature new-reply text) until `busy` flips to false right as audio starts; also give `_initialGreeting` APOLO's calm/teasing personality flavor.
- **S5 — Tests:**
  - `test/features/apolo/soul_personality_test.dart`: verifies `soul.md` exists, `coreSkill` + `ApoloUrineSkill` instructions include the Navi/TARS-inspired calm/teasing persona and critical-safety guard, and `ApoloUrineOfflineFlow` responds in character.
  - Extend `test/features/agent/resilient_agent_services_test.dart`, `test/features/agent/application/agent_runtime_test.dart`, and `test/features/apolo/presentation/apolo_home_screen_test.dart`: prove `speakSynchronized` delays `onAudioReady` and `isSpeaking` until synthesis completes, `AgentConversationController` keeps `busy == true` and withholds the assistant message until `onAudioReady`, commits safely if synthesis throws, and `ApoloHomeScreen` shows `isThinking: true` + thinking indicator until audio is ready, then reveals text + `isSpeaking` together.
